# define-feature

**Reach for it when** one feature needs working through: each job it does for a person, step by step, and what happens when things go another way. For the whole work, use [scope-work](scope-work.md).

**Say** "Define the refunds feature." Later, answer by number, or say "picture" for the process diagram.

**What comes back first** is the feature's intent, each job as numbered steps with who does each and where it branches, the rules found, and at most three questions, each with a recommended answer. "Yes" takes the recommendation.

**How to tell it is working**

- Your records hold a process for every job, with a condition on every branch.
- Each rule behind a branch is a requirement, with an example on each side of it.
- When no question is left it says so, and points you to [slice-requirements](slice-requirements.md) for the handover brief.

**It will not** record screens, storage or how a system does its part as requirements. Those are noted as left to engineering.

**Good to know**

- A job is one named person, in one situation, wanting one result.
- A new branch of a job that already has a process goes into that process, with a way in and a way back, not into a second one.
- A question asked is a question recorded, with a working answer, so work can go on while its owner confirms.
- An example the assistant added shows "To confirm" until you confirm it.
- It looks for gaps in a fixed order: a process with no result for anyone, a branch with no condition, a condition with no rule, a rule with no example.
